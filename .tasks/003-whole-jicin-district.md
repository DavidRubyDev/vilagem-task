## Goal

The map shows the parcels of the whole Jičín district (okres 3604): 240 cadastral areas of 111
municipalities, 272,011 parcels. The land types are correct at every zoom.

**Coverage list.** It is generated from RÚIAN by a new command (`make coverage`) and committed.

**Import.**
- `make data` reads each municipality file once and reports its progress.
- It refuses to publish a tileset whose tiles exceed the 200 kB smoothness budget.
- It prints tile statistics per zoom.

**Smoothness evidence.** Besides the import-time gate, a repeatable browser measurement
(`make perf`) and a manual Chrome check record it.

## Decisions

1. **The coverage list is generated by a command and committed.**
   - What runs: `bin/console coverage:generate --district=3604`, wrapped by `make coverage`. It
     downloads the ČÚZK state structure file `{YYYYMMDD}_ST_UZSZ.xml.zip` and writes
     `config/coverage.csv`.
   - Why committed: the import stays reproducible, and every change to the list is a reviewable
     diff.
   - `make data` never runs it. The operator runs `make coverage` deliberately, reviews the diff
     and commits it.
   - `config/README.md` records the command and the export date of the committed version.
2. **Only cadastral areas with a digital map** (`ExistujeDigitalniMapa = true`) are listed.
   Areas without one have no parcel polygons (VFR FAQ 24). All 240 areas of district 3604 have
   one.
3. **CSV format unchanged** (`code,name,municipality_code`):
   - rows sorted by area code;
   - UTF-8, LF line endings, trailing newline;
   - a field is quoted only when it contains a comma, a double quote or a line break, with
     double quotes doubled. Not `fputcsv`, which also quotes names containing spaces.
4. **Each municipality export is converted once.** One `ogr2ogr` run per municipality, filtered
   by `KatastralniUzemiKod IN (…)`; parcels are then counted per area. This takes conversion
   from 49 s to 22 s for the district.
5. **Progress is an Application port passed to the use case**:
   `execute(ImportParcelsInput $input, ImportProgress $progress)`.
   - It is implemented in the Command layer (`ImportProgressUsingConsole`), because formatting
     for the operator is presentation.
   - Progress goes to stdout.
   - The final per-area list (240 lines) stays as the import record.
6. **Failure handling.**
   - A failed download or conversion stops the import; there are no automatic retries.
   - Downloads are cached as they complete, so rerunning resumes.
   - All municipalities use one export date, for consistent borders and one "ČÚZK, year" credit.
   - The fallback rule is unchanged: only the first municipality may fall back to the previous
     month, and the rest use its date.
   - Publication window: ČÚZK publishes the monthly files over about an hour on the 1st. If a
     later municipality is not yet published, the import fails with `ExportNotPublished`. The
     README tells the operator to rerun later or pass `--export-date`.
7. **The tile size budget is a domain value object** (`TileSizeBudget::smoothMap()` = 200,000
   bytes, gzip).
   - It is the single source of truth for tippecanoe's `--maximum-tile-bytes` and for the gate.
   - After the build, the import inspects the tileset. If any tile exceeds the budget, it fails
     with `TilesetOverBudget` and publishes nothing.
   - The output lists, per zoom, the tile count and the largest tile.
8. **The tile build drops the smallest parcels instead of merging them** (`--drop-smallest-as-needed`).
   - Merging (`--coalesce-densest-as-needed`) painted blocks of several km² with one parcel's
     land type at zoom 9–11.
   - Dropping keeps every remaining parcel with its true land type, and the base map shows
     through the gaps.
   - Reduction happens only at zoom 9–13. Zoom 14–16 is untouched, so outlines from zoom 14 stay
     correct.
   - The build takes 18 s instead of 65 s.
9. **The initial view stays Jičín at zoom 12. No URL hash.** `make perf` opens its views by
   rewriting `initialView` in its own interception of `/api/map-config`, so no production
   change is needed.
10. **Smoothness evidence has three parts:**
    - the import-time gate (Decision 7);
    - `make perf`: asserts budgets that do not depend on hardware, and records frame and
      long-task numbers as a report only. Docker's headless Chromium renders WebGL in software,
      so frame times are not representative.
    - a manual check in Chrome on real hardware, recorded in the implementation log.
11. **Serving stays as it is.** Chrome opens at most 6 connections per host, the server has 8
    workers, and tile URLs are immutable and versioned. Measured tile responses: median
    12–28 ms, maximum 47 ms.
12. **New intermediate directory `data/build/municipalities/{code}.geojsonl`.** It avoids clashes
    with task 002's per-area files in `data/build/parcels/`. Build files and old cache months are
    kept (task 002 Decision 6) and documented with their sizes.
13. **The ST_UZSZ file is cached in `data/cache/ruian/`**, next to the municipality files, under
    the same rules.
14. **One shared download helper.** Downloading is extracted from
    `RuianExportDownloaderUsingHttp` into `Infrastructure\Http\ZipFileDownloader`, used by both
    downloaders. Its behaviour is unchanged.
15. **The Compose `!reset` risk from task 002 is closed.** CI passed on PR #3 and on `main` with
    the `parcel-map-test` project (Compose 2.38.2 on the runner). Even without the reset, port
    8000 conflicts with nothing on a runner.

## Architecture

Paths and namespaces are binding. Conventions from tasks 001/002 apply:
- value objects are `final readonly` with `equals()` where they are compared;
- exceptions are `final class … extends \InvalidArgumentException` (invalid values) or
  `\RuntimeException` (failures), with named constructors that build the message;
- the CLAUDE.md naming rules apply.

Method bodies, private helpers and test code are left to the implementation.

### Domain

**`ParcelMap\Domain\Cadastre`**

| Class | Step | Constructor / factories | Invariants and behaviour |
|---|---|---|---|
| `DistrictCode` | 1a | `__construct(public int $value)` | `1000 ≤ value ≤ 9999` → `InvalidDistrictCode::notFourDigits(int)`. `equals()`. |
| `Coverage` (existing) | 1a | new `static sortedByCode(CadastralArea ...$areas): self` | Same invariants as the constructor; the areas are ordered by code ascending. |
| `Coverage` (existing) | 2 | new `areasOf(MunicipalityCode $municipality): non-empty-list<CadastralArea>` | The covered areas of that municipality in coverage order. A municipality that is not covered → `MunicipalityNotCovered::code(int)` (`final class … extends \InvalidArgumentException`). |

- `CoverageRepository` (step 1a) gains `save(Coverage $coverage): void`, which throws
  `CoverageNotSaved` (`final class … extends \RuntimeException`, `::because(string $reason)`).
  `get()` is unchanged.

**`ParcelMap\Domain\Map`** (step 4)

| Class | Constructor / factories | Invariants and behaviour |
|---|---|---|
| `TileSizeBudget` | `__construct(public int $maxBytes)`; `static smoothMap(): self` | `maxBytes ≥ 1` → `InvalidTileSizeBudget::notPositive(int)`. `smoothMap()` = 200,000. Its comment says why: at most about 20 tiles are visible at 1920×1080, so a view stays under 4 MB, which MapLibre parses and draws smoothly. `allows(int $bytes): bool` (`bytes ≤ maxBytes`). `equals()`. |
| `ZoomTileStatistics` | `__construct(public int $zoom, public int $tileCount, public int $largestTileBytes, public TileCoordinate $largestTile)` | `tileCount ≥ 1`, `largestTileBytes ≥ 1`, `largestTile->zoom === zoom` → `InvalidTilesetStatistics::…` (named constructors per rule). |
| `TilesetStatistics` | `__construct(ZoomTileStatistics ...$zooms)` | At least one → `InvalidTilesetStatistics::empty()`. Unique zooms → `::duplicateZoom(int)`. Methods: `zooms(): non-empty-list<ZoomTileStatistics>` (ascending by zoom, whatever the given order); `tileCount(): int` (sum); `largest(): ZoomTileStatistics` (the zoom with the biggest largest tile, lowest zoom on ties); `fitsWithin(TileSizeBudget $budget): bool` (`budget->allows(largest()->largestTileBytes)`). |

### Application

**Coverage** (new namespace `ParcelMap\Application\Coverage`, step 1a)

Ports:

```php
interface RuianStructureDownloader
{
    /** @throws StructureNotPublished|StructureDownloadFailed */
    public function download(ExportDate $date): DownloadedStructure;
}

interface DistrictAreaExtractor
{
    /**
     * The cadastral areas with a digital map of every municipality in the district; empty when there are none.
     *
     * @return list<CadastralArea>
     * @throws StructureReadFailed
     */
    public function extract(DownloadedStructure $structure, DistrictCode $district): array;
}
```

- Handle: `DownloadedStructure(ExportDate $date, string $path, bool $fromCache)` (`final readonly`,
  public promoted properties; the path is opaque to the use case).
- Use case `final readonly class GenerateCoverageUseCase`:
  - Constructor: `(RuianStructureDownloader $downloader, DistrictAreaExtractor $extractor, CoverageRepository $coverage, Clock $clock)`.
  - `execute(GenerateCoverageInput $input): GenerateCoverageOutput`.
  - Algorithm:
    1. `new DistrictCode($input->district)`; an `InvalidDistrictCode` becomes
       `InvalidCoverageRequest::invalidDistrict(int $given, string $reason)`.
    2. Export date as in `ImportParcelsUseCase`. `null` → `ExportDate::latestPublishedOn($clock->now())`
       with one fallback to `previous()` on `StructureNotPublished`. Otherwise
       `ExportDate::fromString()` (an `InvalidExportDate` becomes
       `InvalidCoverageRequest::invalidExportDate(string $given, string $reason)`) and no
       fallback.
    3. Download, then extract.
    4. An empty list → `DistrictNotFound::for(int $district, string $date)`, with the message
       `District 3605 has no cadastral areas in the RÚIAN export of 2026-10-31.`. Nothing is
       saved.
    5. `Coverage::sortedByCode(...$areas)`, then `$coverage->save()`. A `CoverageNotSaved`
       becomes `CoverageWriteFailed::because(string)`.
    6. Return the output.
  - Input: `GenerateCoverageInput(int $district, ?string $exportDate)`.
  - Output: `GenerateCoverageOutput(string $exportDate /* Y-m-d */, int $district, int $areaCount, int $municipalityCount)`.
- Exceptions (all in this namespace):
  - `InvalidCoverageRequest extends \InvalidArgumentException`.
  - `abstract class CoverageGenerationFailed extends \RuntimeException`, with final subclasses:
    - `StructureNotPublished::for(string $date)`: "The RÚIAN state structure file of 2026-09-30
      is not published."
    - `StructureDownloadFailed::because(string)`
    - `StructureReadFailed::because(string)`
    - `DistrictNotFound::for(int, string)`
    - `CoverageWriteFailed::because(string)`

**Import** (`ParcelMap\Application\Import`, existing)

*Step 2: one conversion per municipality.*

- Port: `ParcelConverter::convert(DownloadedExport $export, array $areas): ConvertedParcels`, with
  `@param non-empty-list<CadastralArea> $areas`, the covered areas of the export's municipality.
  It throws `ConversionFailed|CadastralAreaNotInExport` (the latter for the first given area
  without parcels).
- `AreaParcelCount(CadastralAreaCode $area, int $parcelCount)` (`final readonly`):
  `parcelCount ≥ 1`, otherwise `\InvalidArgumentException`.
- `ConvertedParcels(MunicipalityCode $municipality, string $path, array $areaCounts)` replaces the
  per-area shape, with `@param non-empty-list<AreaParcelCount> $areaCounts`.
  - Invariants: non-empty, unique areas, otherwise `\InvalidArgumentException`.
  - `parcelCountOf(CadastralAreaCode $area): int` throws `\OutOfBoundsException` for an area not
    in the list (a contract violation by the adapter).
  - `totalParcelCount(): int`.
- `TilesetBuilder::build(array $parcels)` still receives `non-empty-list<ConvertedParcels>`, now
  one per municipality.
- Use case algorithm (replacing steps 4–5 of task 002):
  - Convert each municipality of `Coverage::municipalities()` in order, with
    `$coverage->areasOf($municipality)`.
  - Build `ImportedAreaOutput` in coverage area order from the matching `ConvertedParcels`
    (`parcelCountOf`).
  - The total is the sum.
  - Build from the converted files in municipality order.

*Step 3: progress.*

- New port:

  ```php
  interface ImportProgress
  {
  ```

### Infrastructure

**`Infrastructure\Http`** (step 1a, extracted from `RuianExportDownloaderUsingHttp`)

- `ZipFileDownloader` is an internal helper that implements no port.
  - Method: `download(string $url, string $cachePath): FetchedFile`.
  - Behaviour is exactly that of today's adapter:
    - a cached file means no request;
    - creates the cache directory;
    - `.part` file, `CURLOPT_FOLLOWLOCATION` (max 3), connect 10 s, total 300 s;
    - User-Agent `parcel-map-importer`;
    - zip signature check, `rename()` on success, `.part` removed on failure.
  - 404 → `RemoteFileNotFound::at(string $url)`; a transport error, other status or non-zip body
    → `RemoteFileUnavailable::because(string)`. Both are `final … extends \RuntimeException`,
    internal to Infrastructure.
- `FetchedFile(string $path, bool $fromCache)` (`final readonly`).
- `Import\RuianExportDownloaderUsingHttp(ZipFileDownloader $downloader, string $baseUrl, string $cacheDir)`
  translates `RemoteFileNotFound` → `ExportNotPublished` and `RemoteFileUnavailable` →
  `SourceDownloadFailed`. Messages and file names are unchanged, so the existing integration
  tests pass unchanged apart from construction. In step 3 it sets
  `DownloadedExport::$fromCache` from `FetchedFile`.

**`Infrastructure\Coverage`** (step 1a)

- `RuianStructureDownloaderUsingHttp(ZipFileDownloader $downloader, string $baseUrl, string $cacheDir)`:
  - file `{YYYYMMDD}_ST_UZSZ.xml.zip`, URL `$baseUrl . $fileName`, cache path
    `$cacheDir/$fileName`;
  - 404 → `StructureNotPublished`; others → `StructureDownloadFailed`;
  - returns `DownloadedStructure` with `fromCache`.
- `DistrictAreaExtractorUsingOgr2ogr(ProcessRunner $runner)`. Two runs, both
  `ogr2ogr -f CSV /vsistdout/ /vsizip/<path>/<file name without .zip> -dialect OGRSQL -sql …`:
  1. `SELECT Kod FROM Obce WHERE OkresKod = <district>`. Zero rows → return `[]` without
     running the second.
  2. `SELECT Kod, Nazev, ObecKod FROM KatastralniUzemi WHERE ExistujeDigitalniMapa = 'true' AND ObecKod IN (<codes, comma-separated>)`.

  Parsing and errors:
  - stdout is parsed as CSV (`fgetcsv` on a `php://temp` stream, `escape: ''`);
  - the headers must be exactly `['Kod']` and `['Kod', 'Nazev', 'ObecKod']`;
  - builds `CadastralArea`s in the order of the output;
  - a non-zero exit (stderr in the message), a wrong header, a row of the wrong width,
    non-numeric codes or a domain exception → `StructureReadFailed`.

  The class comment explains why there are two queries (GDAL's SQL cannot filter on a joined
  layer).

**`Infrastructure\Cadastre\CoverageRepositoryUsingCsv`** (step 1a): `save(Coverage $coverage)`.

- Writes `$file . '.tmp'`: the header `code,name,municipality_code`, then one row per area in
  `areas()` order, as `code,name,municipality_code`.
- Line endings `\n`, trailing newline, UTF-8.
- A field is quoted only if it contains `,`, `"`, `\r` or `\n`, with `"` doubled.
- Then `rename()` onto `$file`.
- Any failure (cannot write, cannot rename) → `CoverageNotSaved::because(...)` naming the file;
  the `.tmp` file is removed.

**`Infrastructure\Import\ParcelConverterUsingOgr2ogr`** (step 2)

- Output `$workDir/municipalities/{municipality}.geojsonl` (directory created if missing).
- Runs:

  ```
  ogr2ogr -f GeoJSONSeq <output> /vsizip/<export path>/<export file name without .zip>
    -sql "SELECT Id AS id, DruhPozemkuKod AS landType, KatastralniUzemiKod AS areaCode, OriginalniHranice FROM Parcely WHERE KatastralniUzemiKod IN (<codes>)"
    -dialect OGRSQL -t_srs EPSG:4326 -lco COORDINATE_PRECISION=7
  ```

- Exit code ≠ 0 → delete the output, `ConversionFailed` with stderr.
- Then read the file line by line (`fgets`, skip blank lines, `json_decode` with
  `JSON_THROW_ON_ERROR`) and count `properties.areaCode`. A malformed line or missing `areaCode`
  → `ConversionFailed`.
- The first requested area with zero parcels (in the given order) → delete the output,
  `CadastralAreaNotInExport::for(area, municipality, date)`.
- Returns `ConvertedParcels` with the counts in the given area order.
- tippecanoe keeps only `landType` (`--include=landType`), so `areaCode` never reaches the tiles.

**`Infrastructure\Import\TilesetBuilderUsingTippecanoe`**

- Step 4: `build($parcels, TileSizeBudget $budget)` passes
  `--maximum-tile-bytes=<budget->maxBytes>`.
- Step 5: `--coalesce-densest-as-needed` is replaced by `--drop-smallest-as-needed`. All other
  options are unchanged.
- The class comment is rewritten for step 5:
  - when a tile would exceed the budget, the smallest parcels are left out, which in practice
    happens only below zoom 14;
  - parcels are never merged, so every drawn parcel keeps its own land type;
  - shared borders, ids and `landType` as before.

**`Infrastructure\Import\TilesetInspectorUsingMbtiles`** (step 4, implements `TilesetInspector`)

- Opens `$tileset->path` read-only:
  `new Pdo\Sqlite('sqlite:' . $path, options: [Pdo\Sqlite::ATTR_OPEN_FLAGS => Pdo\Sqlite::OPEN_READONLY, PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION])`.
  A missing file → `TilesetInspectionFailed`, and the file is not created.
- Per zoom: `SELECT zoom_level, COUNT(*), MAX(LENGTH(tile_data)) FROM tiles GROUP BY zoom_level ORDER BY zoom_level`.
- Then the largest tile of each zoom:
  `SELECT tile_column, tile_row FROM tiles WHERE zoom_level = ? ORDER BY LENGTH(tile_data) DESC, tile_column, tile_row LIMIT 1`,
  with y = 2^z − 1 − `tile_row`.
- No rows → `TilesetInspectionFailed` ("contains no tiles"). Any `PDOException` or domain
  exception → `TilesetInspectionFailed`. (`tiles` is a view in tippecanoe output; the queries
  work on it.)

**Data layout** (data dir as in task 002):
- `cache/ruian/` holds the municipality files and `{YYYYMMDD}_ST_UZSZ.xml.zip`;
- `build/municipalities/` holds the converted GeoJSON lines;
- `build/parcels/` (task 002 leftovers) is no longer written;
- `tiles/parcels.mbtiles` is the published tileset.

## Risks and assumptions

- **Memory.** The tile build needs about 0.9–1.7 GB depending on CPU threads. Docker Desktop
  with a small memory limit could kill it (tippecanoe exits non-zero, and `TileBuildFailed`
  makes it visible).
- **Publication window.** Between about 01:00 and 02:20 UTC on the 1st, some municipality files
  of the new month are missing, and the import fails. This is documented.
- **Coverage drift.** If ČÚZK changes cadastral areas, the committed list can disagree with a
  newer municipality export. A listed area without parcels fails the import
  (`CadastralAreaNotInExport`). An area added to a covered municipality is silently missing
  until `make coverage` is rerun.
- **Software WebGL in Docker.** `make perf` frame numbers do not represent real GPUs, so only
  network and data budgets are asserted. Real smoothness relies on the manual check.
- **Narrow screens.** The district fits only below zoom 9 on a phone in portrait, where parcels
  are not drawn. The initial view (Jičín, zoom 12) is unaffected.
- **Dropped parcels at zoom 12–13.** In town centres, the smallest parcels are missing at zoom
  12–13 (the base map shows through). This was accepted as honest.
- **tippecanoe output varies slightly between runs** (parallel reading); sizes differ by a few
  KB. Tests use the committed fixture tileset or assert properties, not bytes.
- **Download time** for 111 files was not measured during planning (estimated at about 1 min).
- **Assumption:** ČÚZK keeps the ST_UZSZ file name, its layers and the field names `OkresKod`,
  `ObecKod` and `ExistujeDigitalniMapa`. A change makes `make coverage` fail loudly
  (`StructureReadFailed` / `StructureNotPublished`).
